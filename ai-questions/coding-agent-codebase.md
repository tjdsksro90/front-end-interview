# Q : AI 코딩 에이전트와 함께 일할 때 코드베이스는 어떻게 관리하나요?

<br />

# A : 에이전트는 매번 새로 코드베이스를 읽고 일하기 때문에, **에이전트가 읽을 정보를 코드베이스 안에 정리해 두는 것**이 핵심입니다. 첫째, `CLAUDE.md`나 `AGENTS.md` 같은 규칙 파일에 빌드·테스트 명령, 코드 스타일, 하지 말아야 할 것을 짧고 구체적으로 적어 둡니다. 둘째, 에이전트가 스스로 결과를 확인할 수 있게 테스트·타입 검사·린트를 명령 한 줄로 돌릴 수 있게 만듭니다. 셋째, 오래된 TODO·죽은 코드 같은 기술 부채를 줄입니다. Google 엔지니어들의 분석에 따르면 에이전트는 코드 속 오래된 TODO를 보고 요청과 상관없는 작업으로 새는 경우가 있었고, 그때 단계·토큰·대기 시간이 크게 늘었습니다. 결국 **사람이 읽기 좋은 코드베이스가 에이전트에게도 좋은 코드베이스**입니다.

### 1. 규칙 파일: 에이전트용 README

| 파일 | 읽는 도구 | 특징 |
|---|---|---|
| `CLAUDE.md` | Claude Code | 프로젝트 루트(`./CLAUDE.md`)·사용자 전역(`~/.claude/CLAUDE.md`)·개인용(`CLAUDE.local.md`). 위 폴더의 파일은 시작할 때, 하위 폴더 파일은 그 폴더 작업 시 읽음. `@경로`로 다른 파일 포함 |
| `AGENTS.md` | Codex, Cursor, Gemini CLI, GitHub Copilot 코딩 에이전트, Jules 등 여러 도구 | "에이전트를 위한 README". 패키지마다 둘 수 있고, 수정하는 파일에서 **가장 가까운 파일이 우선** |

```md
# AGENTS.md (예시)

## 명령어
- 개발 서버: `npm run dev`
- 테스트: `npm test` (커밋 전 반드시 통과)
- 타입 검사: `npm run typecheck`

## 코드 스타일
- 컴포넌트는 함수형 + named export
- 스타일은 Tailwind만 사용, 인라인 style 금지
- 2칸 들여쓰기

## 하지 말 것
- `src/generated/`는 자동 생성 파일이라 직접 수정하지 않는다
- 새 라이브러리는 추가하기 전에 물어본다
```

- **짧고 구체적으로**: Claude Code 문서는 파일 하나를 200줄 이내로 유지하라고 권한다. "코드를 깔끔하게"보다 "2칸 들여쓰기"처럼 확인할 수 있게 쓴다.
- **강제가 아니라 맥락이다**: 규칙 파일은 에이전트가 참고하는 정보일 뿐이다. 반드시 지켜야 하는 것(특정 파일 수정 금지, 위험한 명령 차단)은 도구의 권한 설정이나 hook, CI로 막는다.
- 오래된 규칙이 남으면 오히려 혼란을 준다. 코드처럼 리뷰하고 갱신한다.

### 2. 에이전트가 스스로 확인할 수 있게

- 에이전트는 코드를 쓴 뒤 **테스트·타입 검사·린트 결과를 보고** 고친다. 확인 수단이 없으면 "그럴듯하지만 틀린" 코드가 남는다.
- 명령 하나로 돌릴 수 있게 (`npm test`, `npm run lint`) 만들고, 규칙 파일에 적어 둔다.
- 실패 메시지가 구체적일수록 에이전트가 잘 고친다. E2E·스크린샷 테스트가 있으면 UI 변경도 스스로 확인한다.
- 작은 단위로 요청하고 PR 단위로 리뷰한다. 거대한 변경을 한 번에 맡기면 리뷰가 불가능해진다.

### 3. 기술 부채가 에이전트를 흔든다 ("agent distraction")

Google 엔지니어들이 내부 에이전트 세션을 분석한 결과(InfoQ, 2026년 11월):

- 세션의 약 13%에서 에이전트가 코드 속 TODO/FIXME 참조를 마주쳤고, 그중 6%에서 요청받지 않은 그 버그를 고치러 갔다.
- 그렇게 샌 작업의 41%는 **이미 닫힌 이슈**, 57%는 요청 범위 밖의 열린 버그였다.
- 이런 이탈이 생기면 단계는 70%, 토큰은 77%, 대기 시간은 105% 늘었다.
- 해결책으로 오래된 TODO를 찾아 지우는 에이전트를 돌려 6개월 동안 수천 개를 정리했고, 사람 리뷰어의 승인율이 95%를 넘었다.

그래서:

- 닫힌 이슈를 가리키는 TODO, 주석 처리된 코드, 쓰지 않는 파일을 지운다.
- 오래된 문서·스펙은 고치거나 지운다. 에이전트는 무엇이 낡았는지 모른다.
- 같은 일을 하는 함수가 여러 개면 하나로 합친다. 에이전트가 엉뚱한 쪽을 고친다.

### 4. 최신 웹 기능을 쓰게 하기

- 에이전트는 학습 데이터에 많은 **오래된 패턴**(예: CSS `field-sizing`으로 될 일을 JS로 textarea 높이 계산, 브라우저 기본 기능으로 될 일에 라이브러리 추가)을 쓰기 쉽다.
- Chrome 팀은 2026년 11월 **Modern Web Guidance**(v1.0)를 정식 공개했다. 웹 플랫폼 모범 사례와 브라우저 호환성 데이터를 에이전트의 skill로 넣어, 오래된 패턴 대신 최신 브라우저 기능을 쓰도록 돕는다. 기존 코드를 최신 방식으로 바꾸는 작업 흐름도 들어 있다. Firefox·Edge 팀도 참여한다.
  ```bash
  npx modern-web-guidance@latest install
  ```
- 규칙 파일에 "지원 브라우저", "쓰지 않는 라이브러리"를 적어 두는 것도 같은 효과가 있다.

### 5. 보안·권한

- 에이전트에게 `.env`, 운영 DB 접근 권한을 주지 않는다. 필요한 최소 권한만.
- 에이전트가 만든 코드도 사람이 리뷰한다. 특히 인증, 결제, 데이터 삭제 부분.
- 외부에서 가져온 문서·이슈 본문에 숨은 지시(프롬프트 인젝션)가 있을 수 있다.

- 면접 답변 요약: "에이전트는 매번 코드베이스를 새로 읽으니 읽을 정보를 정리해 두는 게 핵심입니다. CLAUDE.md나 AGENTS.md에 빌드·테스트 명령, 코드 스타일, 금지 사항을 짧고 구체적으로 적고, 반드시 막아야 할 건 권한 설정이나 CI로 강제합니다. 테스트·타입 검사·린트를 한 줄로 돌릴 수 있게 해서 에이전트가 스스로 검증하게 하고, 오래된 TODO나 죽은 코드를 정리합니다. Google 분석에서도 오래된 TODO 때문에 에이전트가 범위 밖 작업으로 새면 토큰과 시간이 크게 늘었습니다. 사람이 읽기 좋은 코드베이스가 에이전트에게도 좋습니다."
