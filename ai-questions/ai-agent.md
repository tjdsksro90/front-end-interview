# Q : AI Agent란 무엇이고, 하네스(Harness)는 무엇인가요?

<br />

# A : AI Agent는 LLM이 도구를 골라 쓰고 그 결과를 보며 목표를 이룰 때까지 스스로 반복하는 시스템이고, 하네스는 그 모델을 둘러싸고 실행시키는 틀(도구, 컨텍스트, 권한, 검증)입니다.

### AI Agent

- 일반 챗봇은 질문 한 번에 답을 한 번 만든다. 에이전트는 **"생각 → 도구 호출 → 결과 확인"을 반복**하며 일을 끝낸다.
- 어떤 도구를 어떤 순서로 쓸지 **모델이 스스로 정한다.** 예: 버그 수정을 맡기면 파일을 읽고 → 코드를 고치고 → 테스트를 돌리고 → 실패하면 다시 고친다.

```text
목표 입력
  → 모델: "파일을 읽어야겠다" → read_file 호출 → 결과를 컨텍스트에 추가
  → 모델: "여기를 고치자"     → edit_file 호출 → 결과 추가
  → 모델: "테스트 돌려보자"   → run_tests 호출 → 실패 로그 추가
  → ... (목표를 이루거나 멈춤 조건까지 반복)
  → 최종 답변
```

- 구성 요소: **모델(LLM)**, **도구(tool)**, **컨텍스트(지금까지의 대화와 결과)**, **반복 루프와 멈춤 조건**

#### 워크플로우와의 차이

| | 워크플로우 | 에이전트 |
|---|---|---|
| 순서를 정하는 쪽 | 개발자가 코드로 미리 정함 | 모델이 실행 중에 정함 |
| 장점 | 예측 가능, 빠르고 저렴 | 정해지지 않은 문제도 해결 |
| 어울리는 일 | 요약 → 번역처럼 단계가 정해진 일 | 코딩, 조사처럼 단계가 그때그때 달라지는 일 |

- 단계가 정해져 있으면 워크플로우가 더 안정적이다. 에이전트는 꼭 필요할 때 쓴다.

### 하네스(Harness)

- 모델 자체가 아니라, **모델을 실행시키고 도구와 연결하는 바깥 프로그램**이다. Claude Code, Codex 같은 코딩 에이전트가 대표적인 하네스다.
- 하네스가 하는 일:
  - **도구 제공·실행**: 파일 읽기/쓰기, 터미널, 검색 같은 도구를 정의하고, 모델이 호출하면 실제로 실행한다.
  - **컨텍스트 관리**: 프로젝트 규칙(AGENTS.md, CLAUDE.md), 필요한 파일만 골라 넣고, 길어지면 요약한다.
  - **권한·안전장치**: 위험한 명령은 사용자 승인을 받고, 접근할 수 있는 범위를 제한한다.
  - **검증과 피드백**: 린트, 테스트, 빌드 결과를 모델에게 돌려줘 스스로 고치게 한다.

### 하네스 엔지니어링

- 같은 모델이라도 하네스를 어떻게 만드느냐에 따라 결과가 크게 달라진다. 그래서 **모델을 바꾸는 것보다 모델 주변을 설계하는 것**에 집중하는 것을 하네스 엔지니어링이라고 한다.
- 예: 프로젝트 규칙 문서 작성, 테스트를 빠르게 돌릴 수 있게 하기, 파일 수정 후 자동으로 린트 실행(hook), 작업을 작게 나눠 맡기기
